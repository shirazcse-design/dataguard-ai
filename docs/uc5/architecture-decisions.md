# UC5 architecture decisions (approved 2026-10-07)

| # | Decision | Why | Where it is enforced |
|---|---|---|---|
| a | **UC2's users are the canonical UC5 subjects.** UC3's access engine runs, unchanged, over a small UC5 access dataset for those users (`data/incident/access`, UC3 schema, as of 2026-08-01). No entity-resolution table. | UC1 (u-10xx), UC2 (u-20xx) and UC3 (u-30xx) were built as separate synthetic worlds; stitching them would mix unrelated stories. UC2 already has behaviour, logs, identity and approvals for the same people and days. | `app/incident/synth.py`, `services.py` (`AccessGraph(base=...)`) |
| b | **Severity LOW / MEDIUM / HIGH / CRITICAL, separate from review status** (NOT_REQUIRED / REQUIRED / PENDING / COMPLETED). The harness sets LOW–HIGH floors; the agent can raise, never lower; **CRITICAL is analyst-only.** | POL-IR §3 defines Severity 1 as *confirmed* loss of Restricted information; confirmation is a person's act. | `app/incident/schemas.py` (the agent's schema cannot say CRITICAL), `harness.py`, `config/incident/rubric.v1.yaml` |
| c | **UC1: deterministic DLP facts only** (the destination catalogue; UC1's templated policy question and effect mapping, through UC6). UC1's overall risk score and its employment-status / notice-period signal are **not** used. UC1 is not modified. | Severity must rest on security evidence, not HR characteristics. UC2 already excluded HR inputs; UC5 follows UC2, and the UC1/UC2 difference stays recorded as UC1 follow-up work. | `services.py` (only `app.dlp.prechecks.classify_destination`); a test checks no HR field or UC1 investigator is referenced |
| d | **No UC5 MCP server.** UC4 is called through its existing MCP adapter with a new caller (`incident-investigation-agent`, added to `config/mcp/mcp.v1.yaml`). UC5's own tools are bounded in-process tools on the shared agent loop. | MCP is already demonstrated in UC4 (server), UC1 and UC2 (tool exposure). A UC5 server would duplicate it without new learning. | `services.py` (`CALLER`), `tools.py` |
| e | **The Foundry agent, guardrail and evaluations are created manually in the portal.** `dataguard-incident agent export` writes the instructions, tool schemas and I/O schemas; nothing is provisioned from code. | Product-owner decision for UC5. | `app/incident/cli.py` |

Refinements also built in: a **minimal case packet** (the agent gathers its own evidence; the harness gathers its own facts afterwards and never depends on the agent's tool choices); **10 tools** (timeline and correlation merged into `build_timeline`; no separate `get_policy_section` because UC6 returns verified claims with text and citation); **golden labels unreachable at runtime** (a test checks it); **one agent**; cost `NOT_ESTIMATED`.
