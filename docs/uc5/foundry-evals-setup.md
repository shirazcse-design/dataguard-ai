## 3. What the judges' reasons say (read from all 64 reasons)

The judges' written reasons were fetched read-only. Unlike UC2's first run, this is **not** an
input-format problem: the judges read the right material and describe the runs accurately. The
failures have three sources:

1. **My instructions and my tool definitions disagree** (the largest share). The prompt lists tool
   signatures without the optional `subject` argument that the tool schemas allow, and it names the
   review conditions in plain words while the tool's enum has different names (for example
   `high_impact_action_needed`). The judges treat the prompt as the contract and fail calls that the
   tool schema accepts: `subject` is named in 5 of the 16 task-adherence reasons and 10 of the
   11 tool-call failures, and tool-signature or parameter mismatches in 9 of the 16. This is a design defect, not model misbehaviour.
2. **Real agent errors:** `check_approval` called with a placeholder reference ("none"), invalid
   arguments (4 locally), and calling most tools whatever the case (about 10 calls per incident),
   which the tool-call judge scores as redundant.
3. **A literal reading of the workflow:** the prompt says "retrieve the transfer, the data, the
   behaviour, the access, the policy"; for a case without a transfer (INC-003) the judge fails the
   run for not retrieving transfer policy.

**Groundedness (4.06, 14/16) is the strongest signal**, consistent with 2 unsupported claims out of
311 locally; the two low rows (INC-005, INC-009) are judged largely grounded with minor issues.

**Not tuned.** Agent v2 was declared the final iteration and the golden labels are frozen. The fix,
recorded as future work: align the prompt's tool signatures and review-reason names with the tool
schemas (and drop the unused `subject` argument), phrase the workflow as "retrieve what the trigger
needs", and reject placeholder references in `check_approval` before the call. The harness decides
severity and review independently, so none of these changes an outcome.
